# 渲染优化结构

`net.hulan.ivr.render_promotion` 按职责组织：


| 包               | 职责                                              |
| ---------------- | ------------------------------------------------- |
| `visibility`     | 方块实体、列车、电梯、轨道及线路片段的可见性策略  |
| `occlusion`      | 遮挡证明与渲染线程上的逐帧射线预算                |
| `bounds`         | 方块实体边界注册                                  |
| `cache`          | 视锥、站牌长度、不可变局部顶点与有界 CPU 网格缓存 |
| `mesh`           | 不可变四边形描述、后台纯数据展开及客户端生命周期  |
| `texture`        | 列车纹理预加载与资源重载失效                      |
| `itf(interface)` | Mixin 暴露的边界、渲染状态及纹理接口              |
| `utils`          | 列车渲染策略兼容门面`TrainRenderPolicy`           |

客户端线程读取世界、计算动画、录制门模型、回放顶点并发布缓存结果。工作线程只接收不可变顶点快照或 `QuadSpec`，不访问世界、方块实体、`ModelMapper`、动态纹理或 GPU。时钟四边形在后台展开，时间与旋转仍实时计算；门的首次模型录制仍在客户端线程，随后复用局部顶点。未就绪时保留原绘制路径和 MTR 图层顺序，门动画在剔除期间继续推进。

缓存为 256 条/8 MiB，等待构建及完成结果为 64 条/8 MiB，单网格最多 65536 个顶点。满载拒绝新工作，不在调用线程执行后台任务。世界切换和资源重载清理缓存及排队任务；完成结果必须匹配代次和仍有效的任务身份。帧末最多接纳 8 个结果或处理 1 ms，不等待工作线程。

这是 CPU 顶点缓存，仍写入现有 `VertexConsumer`，没有 GPU 常驻网格，也不会因此减少 draw calls。时钟网格很小，异步调度本身的收益有限；门缓存主要节省重复模型遍历。尚未进行游戏内性能或视觉测量。

站牌动态纹理与查询行为保留。后续布局缓存应保存版本化的纯数据描述，每帧继续请求当前动态纹理以维护 keepalive 和失效，不能长期保存旧 `DynamicResource`。GPU 常驻缓存需要跨版本适配、上传预算、图层顺序验证，以及淘汰、世界切换和资源重载时在渲染线程显式释放。
